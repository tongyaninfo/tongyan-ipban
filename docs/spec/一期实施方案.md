# 通研 IPBan 一期实施方案

> 状态：实施基线 v0.3（2026-11-08）。本方案已根据用户确认的单机 Agent、防火墙联动、事件能力分级、自动数据库迁移、Windows/Linux 支持范围、当前会话页面和 HTTPS 管理台要求修订。后端四个项目、SQLite 初始化、Linux/Windows 登录与连接采集、Agent/API IPC、Windows Defender Firewall/firewalld 人工临时封禁和当前连接/会话页面已实现；Windows managed 测试包已在隔离测试环境启动并验证 OpenSSH 事件。RDP/WinRM 真实登录、Windows Service、HTTPS 和 Native AOT 仍待验收。本方案描述实施目标，不代表规划能力已全部实现、已验证或已部署。

产品定位见[产品规划](产品规划.md)，需求编号见[功能需求清单](功能需求清单.md)，接口合同见[接口合同](../api/README.md)。本期不支持 macOS、中心管理端和 MCP（MCP 后续已作为可选扩展实现，默认停止）；本期包含 Windows/Linux 防火墙执行器。

## 二、运行拓扑

推荐一个安装包包含两个进程：

```text
IpBan.Api
├── HTTPS 管理 API
├── 登录认证和多用户管理
├── 配置、导出和备份接口
├── 当前连接/会话查询接口
├── 前端静态文件 wwwroot
└── 本机 IPC 客户端

IpBan.Agent
├── 日志采集器
├── auditd/eBPF/WFP/ETW 连接传感器
├── 事件标准化和关联
├── SQLite 写入
├── 纯函数判定引擎调用
├── 防火墙 provider
├── 当前会话查询和人工断开
└── 后台任务
```

`IpBan.Agent` 以 root、Administrator 或等价权限运行。`IpBan.Api` 不接受远程原始命令，只通过本机 Unix Domain Socket 或 Windows Named Pipe 调用类型化 Agent 命令。

管理台默认监听：

```text
https://0.0.0.0:8443
```

端口可配置。`0.0.0.0` 只表示 IPv4，IPv6 `[::]` 不默认绑定。

## 三、事件采集与数据合同

### 3.1 统一登录事件

```text
LoginEvent
├── Id
├── OccurredAtUtc
├── Protocol
├── Success
├── Username
├── RemoteIp
├── RemotePort
├── LocalIp
├── LocalPort
├── LocalProcessId
├── LocalProcessName
├── OriginProcessId
├── OriginProcessName
├── AuthenticationMethod
├── FailureReason
├── Collector
├── RawEventId
├── EvidenceSource
├── CorrelationConfidence
├── CompletenessLevel
└── FieldAvailability
```

语义约定：

- `RemoteIp` 是真实来源地址，不用主机名替代；局域网访问保留局域网地址；回环访问保留 `127.0.0.1` 或 `::1`。
- 远程连接的进程名是本机处理连接的服务进程；远端主机上的进程名不可从本机日志获得。
- 回环连接同时记录本机服务进程和发起连接的本机进程。
- 不使用伪造的 `Unknown`。字段状态使用 `NotProvided`、`NotCollected`、`CorrelationFailed` 或 `NotApplicable`。

### 3.2 事件完整性等级

| 等级 | 条件 | 能否参与封禁 |
| --- | --- | --- |
| `Full` | 用户名、远端地址/端口、本地端点、服务进程和必要关联信息完整 | 可以参与全部策略 |
| `IpEnforceable` | 远端 IP、协议、时间和成功/失败结果可靠 | 可以执行 IP 级别检测和防火墙 Ban，缺失字段明确展示 |
| `ObserveOnly` | 无法可靠取得远端 IP | 只记录和告警，不执行 IP Ban |

默认使用 `IpEnforceable`。管理员可以启用严格模式，要求只有 `Full` 事件才能触发自动策略。

原始事件可以保存为 `RawEvent`。如果完整关联失败，则进入 `EventGap` 或 `UnresolvedEvent`，不伪造业务字段。

### 3.3 Windows 采集器

| 服务 | 主要来源 | 关联来源 |
| --- | --- | --- |
| RDP | Security 4624/4625、TerminalServices Operational | WFP、ETW、4688 |
| OpenSSH | OpenSSH/Operational、Security 4624/4625 | WFP、ETW、4688 |
| WinRM | WinRM/Operational、Security 4624/4625 | WFP、ETW、4688 |

Windows 4624/4625 能提供登录结果、来源地址、来源端口和部分进程信息，但不同事件并不保证所有字段都存在。[4624 事件说明](https://learn.microsoft.com/windows/security/threat-protection/auditing/event-4624)、[4625 事件说明](https://learn.microsoft.com/windows/security/threat-protection/auditing/event-4625)

当前实现先使用 Windows EventLog 加上 `netstat -ano -p tcp` 快照完成可用关联；事件缺少本地端点时标记 `NotCollected`，不伪造字段。后续可在需要更强实时关联时接入 WFP/ETW，进程退出后仍保存采集时的进程名称和路径。

### 3.4 Linux 采集器

SSH 读取优先级：

```text
journald → /var/log/auth.log → /var/log/secure
```

VNC 采用适配器模式支持 TigerVNC、x11vnc、TightVNC 等具体实现。某个实现只提供远端 IP 和登录结果时进入 `IpEnforceable`，仍可按 IP 封禁；如果没有可靠远端 IP，则只能 `ObserveOnly`。

Linux 连接和进程关联使用 auditd、eBPF socket 传感器、`/proc` 和 `ss` 校验。严格模式需要在安装前验证内核、权限和传感器能力。

## 四、判定与封禁流程

```text
日志/系统事件
→ 事件标准化
→ 连接与进程关联
→ 保存 RawEvent/LoginEvent
→ 白名单/黑名单
→ 地域策略
→ 自动策略求值
→ BanDecision
→ FirewallAction
```

优先级：白名单和例外 → 人工黑名单 → 地域封禁 → 自动封禁 → 默认放行。

自动策略包含协议、失败次数、统计窗口、观察期、封禁时长、冷却期、重复触发合并和是否断开已有会话。建议初始模板为：SSH 5 次/5 分钟封禁 30 分钟，RDP 5 次/5 分钟封禁 60 分钟，VNC 5 次/5 分钟封禁 30 分钟，WinRM 5 次/5 分钟封禁 60 分钟。正式默认值需要通过隔离测试确认。

成功手动解封结束该来源此前的处置周期和冷却。解封前的失败不再参与计数，解封后的新失败重新累计，达到阈值仍应封禁；手动解封不等于在剩余冷却时间内免于自动封禁。解封失败或对其他来源的解封不重置本来源冷却，随后产生的新封禁也不受更早的解封影响。

自动策略通过单选按钮选择限时封禁或永久封禁。永久封禁使用 `-1`，保留手动解封路径。限时输入为 `0` 至 `2147483647` 的整数秒，填写 `0` 时该策略仅观察并记录失败。旧版以封禁动作保存的 `0` 仍按永久封禁执行，查询时显示为永久封禁。

判定引擎保持纯函数，不读库、不写文件、不执行命令。调用方构造名单快照、策略版本和观测窗口后交给 `IpBan.Engine`。

## 五、防火墙执行器

### 5.1 Provider

统一接口：

```text
Detect()
GetCapabilities()
Ban()
Unban()
HealthCheck()
```

首期支持：

| 平台 | Provider |
| --- | --- |
| Windows | Windows Defender Firewall/WFP |
| Linux | firewalld |
| Linux | ufw |
| Linux | nftables |
| Linux | iptables |

Linux 探测顺序为 firewalld、ufw、nftables、iptables，只选择一个活动 provider。每个 provider 使用 IPBan 专属链、表或集合，不覆盖用户已有规则。所有参数经过白名单校验，不通过 shell 拼接命令。

### 5.2 防火墙状态

```text
Enabled
Disabled
Unsupported
PermissionDenied
CommandFailed
```

防火墙关闭或执行失败时：

- 继续采集登录事件；
- 继续生成 `BanDecision`；
- `FirewallAction` 标记为 `Disabled` 或 `Failed`；
- 管理台显示 `ProtectionDegraded`；
- 不显示“已写入防火墙”；
- 不自动启动或恢复防火墙；
- 不提供一键恢复；
- 不提供规则对账、历史补写或自动重试队列；
- 防火墙恢复后旧的失败动作不自动下发；
- 后续新封禁请求按正常流程执行。

## 六、当前连接和活动会话

当前情况使用独立页面，与历史登录事件分开。

### 6.1 当前网络连接

展示协议、连接状态、远端 IP/端口、本地 IP/端口、进程 ID、进程名称、连接建立时间和数据来源。支持 TCP 监听、`ESTABLISHED`、`SYN_SENT`、`TIME_WAIT`、`CLOSE_WAIT` 等状态。

Linux 使用 `/proc/net/tcp*`、`ss`、auditd 和 eBPF；Windows 使用 IP Helper API、WFP 和系统连接接口。

### 6.2 当前登录会话

展示协议、用户名、远端 IP、登录时间、会话 ID、服务进程、连接状态和关联事件。支持 SSH、RDP、VNC 和 WinRM。

网络连接和登录会话分开表示：TCP 连接可能已经建立，但认证尚未成功，因而还没有用户名。

### 6.3 已建立连接的处置

普通 Ban 默认：

```text
BanScope = NewConnectionsOnly
```

已经建立的 SSH、RDP、VNC 或 WinRM 会话可能继续存在。页面提供人工“立即断开会话”操作，要求二次确认；支持时删除连接状态，否则使用系统会话或进程终止能力。自动封禁默认不自动断开已有会话。

## 七、SQLite、迁移和日志

### 7.1 启动自动创建和迁移

启动顺序：

```text
创建数据目录
→ 获取单实例迁移锁
→ 创建 SQLite
→ 执行未完成的正向迁移
→ 写入迁移历史
→ 启动 Agent
→ 启动 API
```

使用 WAL 和事务。迁移前生成备份。自动迁移只允许正向、可审计、非破坏性迁移；需要删除数据或不可逆重建时，服务停止并提示人工处理。迁移失败时不启动采集器和防火墙操作。

### 7.2 数据对象

```text
Users
LoginEvents
RawEvents
EventGaps
BanDecisions
FirewallActions
IpLists
Policies
CollectorCursors
SystemCapabilities
Backups
AuditLogs
Settings
```

### 7.3 日志和备份

结构化登录事件保留 365 天，支持自动轮转、压缩、CSV/JSON/NDJSON 导出、数据库备份、备份校验、磁盘大小显示、归档大小显示、最早记录时间、最后备份时间和失败告警。

系统原始日志仍由 Windows/Linux 管理。IPBan 默认保存必要的原始事件标识和结构化证据，不复制全部系统原始日志。

## 八、ID、HTTPS、API 和前端

业务 ID 使用 IIdService/YiteIdService。双进程部署时，ID 生成集中由 Agent 提供，或为 Api/Agent 分配不同且持久化的 WorkerId，禁止不同进程共用同一 WorkerId。



管理 API 使用 Minimal API，统一返回 `ApiResult<T>`，前缀规划为 `/api/admin/v1`。主要分组：认证、用户、名单、策略、封禁、解封、当前连接、当前会话、防火墙状态、存储、备份、HTTPS 和审计。

前端使用 Ant Design Pro 6.0.3、React 19、Umi Max、Biome、中文和英语国际化，页面包括登录、总览、登录事件、当前连接、当前会话、名单、策略、封禁决定、防火墙状态、日志存储、备份、用户、HTTPS 和审计。

前端构建后复制到 `IpBan.Api/wwwroot`，由同源 HTTPS 服务提供，未知前端路由回退 `index.html`。

## 九、Native AOT 与发布

ASP.NET Core 使用 Minimal API、源生成 JSON 和编译期注册 provider。Native AOT 对动态加载、运行时代码生成和部分 ASP.NET Core 功能存在限制，应按官方文档验证。[ASP.NET Core Native AOT](https://learn.microsoft.com/en-us/aspnet/core/fundamentals/native-aot?view=aspnetcore-10.0)、[Native AOT 限制](https://learn.microsoft.com/en-us/dotnet/core/deploying/native-aot/)

避免 `Assembly.LoadFrom`、运行时动态插件和未验证的反射库。Yitter、SQLite、WFP P/Invoke 和 Linux eBPF helper 都要执行实际 AOT 发布验证。

发布目标：

```text
win-x64
win-arm64
linux-x64
linux-arm64
linux-musl-x64
```

Windows 使用 Windows Service，Linux 使用 systemd。前端构建制品和后端 AOT 制品组合为独立运行包。

## 十二、验收标准

验收必须覆盖：

- SSH、RDP、OpenSSH、WinRM、VNC 成功和失败登录；
- 局域网来源、回环来源和回环发起进程；
- 本机服务进程、远端/本地端口和本地端点；
- `Full`、`IpEnforceable`、`ObserveOnly` 事件；
- 防火墙关闭、权限不足、命令失败和不支持；
- 防火墙恢复后不自动恢复、不自动补写；
- 已建立连接继续存在；
- 人工断开 SSH/RDP/VNC/WinRM 会话；
- 当前连接和当前登录会话页面；
- SQLite 首次创建、自动迁移和迁移失败；
- 365 天保留、轮转、压缩、导出和备份；
- HTTPS 自签名证书、证书上传和服务重启；
- `0.0.0.0` 监听、认证、限速和 CSRF；
- Windows/Linux 各 RID 的 Native AOT 发布和启动。

网络层验收必须在获准的隔离主机执行，不在生产或共享主机上验证封禁。未运行的检查不得写成通过。

## 十三、风险和待定项

1. VNC 实现差异可能使部分事件只能达到 `IpEnforceable` 或 `ObserveOnly`；部署前需要确认具体 VNC 软件。
2. Linux eBPF/auditd 能力受内核、发行版和权限影响；严格模式需要安装前置检查。
3. `0.0.0.0` 会让管理台暴露于所有 IPv4 接口；无 RBAC 表示所有账号同权，必须保持 HTTPS 和强认证。
4. 防火墙关闭后只能记录决策和告警，不能声称网络层仍然完成封禁。
5. Yitter、SQLite、WFP 和 eBPF 组件的 Native AOT 兼容性需要真实发布验证。
6. 日志一年留存、导出和备份会影响 SQLite 容量，需要在隔离环境压测后确定默认容量和磁盘告警阈值。
