# 通研 IPBan 产品规划

> 规划版本 v0.3（2026-11-08）。本规划与[一期实施方案](一期实施方案.md)保持一致。后端四个项目、SQLite 基础层、Linux/Windows 登录与连接传感器、Agent/API IPC、防火墙 Provider 基础层和当前连接/会话页面已初始化；Windows managed 测试包已在隔离测试环境验证 API、Named Pipe、Windows 防火墙探测和 OpenSSH 登录事件，RDP/WinRM 真实登录、认证、HTTPS 和正式服务部署仍待验收。

通研 IPBan 是安装在 Windows/Linux 被保护主机上的单机 IP 封禁 Agent，集中采集 SSH、VNC、RDP、OpenSSH 和 WinRM 登录事件，关联连接端点和本机进程，依据名单和策略生成封禁决定，并调用本机防火墙执行 IP/CIDR Ban。

## 一、已确认产品边界

一期包含：

- 单机 Agent，不做中心管理端；
- Windows 和 Linux，不支持 macOS；
- Linux SSH/VNC，Windows RDP/OpenSSH/WinRM；
- Windows Defender Firewall/WFP、firewalld、ufw、nftables、iptables；
- 登录事件、当前网络连接、当前登录会话；
- IP 黑白名单、地域策略、自动封禁和人工封禁；
- SQLite 启动自动创建和正向迁移；
- 日志保留 365 天，轮转、压缩、导出和备份；
- 多用户同权管理，不做 RBAC；
- HTTPS 管理台，默认监听 IPv4 的 0.0.0.0；
- 中文、英语和 Ant Design Pro 主题；
- Native AOT 发布。

一期不包含：

- macOS；
- 中心管理、跨主机策略下发和多实例集中管理；
- MCP/AI（后续已作为可选扩展实现：默认停止，需管理员显式启用并创建受限 API Key，调用进入审计）；
- RBAC；
- 反向代理数据面、WAF 规则引擎和 OWASP CRS；
- 第三方商业防火墙通用适配；
- 防火墙自动恢复、规则对账、历史规则补写和恢复动作审计。

防火墙联动是一期正式能力。界面必须区分 BanDecision、FirewallApplied 和 FirewallFailed/Disabled。

## 二、核心使用流程

1. Agent 从系统日志和连接传感器读取事件。
2. 事件归一化为 Full、IpEnforceable 或 ObserveOnly。
3. 保存原始证据、登录事件和采集缺口。
4. 判定引擎读取只读名单和策略快照。
5. 生成 BanDecision。
6. 调用活动防火墙 provider。
7. 保存 FirewallAction 和最终状态。
8. 管理台显示历史事件、当前连接、活动会话和防火墙状态。

防火墙关闭时继续采集和生成决定，但动作标记为 Disabled，显示 ProtectionDegraded。系统不启动防火墙、不自动恢复、不对账、不补写旧规则、不建立恢复队列。防火墙重新启用后，只处理之后产生的新动作。

当前网络连接与当前登录会话使用独立页面。普通 Ban 默认只阻止新连接；人工确认后可以断开已有 SSH、RDP、VNC 或 WinRM 会话。

## 三、管理台信息架构

登录、总览、登录事件、当前网络连接、当前登录会话、IP 黑名单、IP 白名单、自动封禁策略、封禁决定、防火墙状态、日志与存储、备份、用户、HTTPS 配置、操作审计和系统状态。

页面必须显示空态、失败态、数据缺口、防火墙降级和事件完整性等级。不能只显示“已封禁”，应显示实际的 BanDecision 和 FirewallAction 状态。

## 四、关键决策

### 事件能力分级

- Full：全部核心字段完整；
- IpEnforceable：远端 IP 可靠，可以执行 IP 级别 Ban；
- ObserveOnly：无法取得可靠远端 IP，只记录和告警。

默认允许 IpEnforceable 参与 IP 封禁。缺少的字段显示 NotProvided、NotCollected 或 CorrelationFailed，不伪造 Unknown。

### 防火墙和已有连接

防火墙 provider 只负责探测、Ban、Unban 和健康状态。防火墙关闭时不执行恢复、对账和补写。

已有连接默认继续存在。人工断开是单独的会话操作，不等同于防火墙恢复。

### 存储和发号

SQLite 使用 WAL、单实例迁移锁和事务。启动自动创建数据库并执行正向非破坏性迁移。

业务 ID 使用 YiteId。双进程部署时，ID 生成集中由 Agent 提供，或为 Api/Agent 分配不同且持久化的 WorkerId，禁止不同进程共用同一 WorkerId。
