# 开发与验证脚本

本目录存放仓库级检查脚本。脚本不执行 Git、安装、迁移、部署或删除操作，默认只读。

## 当前脚本

| 脚本 | 预期职责 |
| --- | --- |
| [check-docs.mjs](check-docs.mjs) | 检查仓库 Markdown 的本地相对链接，跳过依赖、构建产物与运行时数据 |
| [scan-open-source-sensitive.mjs](scan-open-source-sensitive.mjs) | 只读扫描凭据、内网地址、个人路径、运行数据等敏感信息，按「阻断/复核」分级 |
| `node scripts/verify.mjs` | 规划中，尚未建立；建立后按文档、后端、前端三个范围调度 |

## 本地链接检查

```bash
node scripts/check-docs.mjs
```

从仓库根运行。脚本扫描当前工作目录下全部 `.md` 文件，检查 Markdown 链接中的相对路径目标是否存在；跳过 `.git`、`.local`、`node_modules`、`bin`、`obj`、`artifacts`、`publish`、`TestResults`、`dist`、`.umi`、`.umi-production`、`.turbopack`、`.cache`、`coverage`、`test-results`、`playwright-report`、`App_Data`、`logs`、`run-data`、`imports`、`exports`。

外部链接、页内锚点、绝对路径、含空格的目标与符号链接不检查。通过时输出检查条数；失败时逐条输出「文件: 相对链接」并以非零退出码结束。链接只校验目标文件存在，不校验锚点、标题或内容；目标尚未创建时按真实缺失处理，不得为了让检查通过而跳过或删除链接。

检查范围仅限本仓库文件，不联网、不访问外部地址；图片引用按同一规则处理。脚本按原文匹配链接语法，正文与代码块中不应写出形似链接的片段，避免误报。新增生成目录时，须先确认它属于依赖或产物，再加入跳过清单，不能按文件名猜测。

## 敏感信息扫描

```bash
node scripts/scan-open-source-sensitive.mjs --root .
```

零依赖、只读、不联网；命中值只输出打码片段，不打印完整敏感值。

- 退出码：`0` 无阻断命中；`1` 存在阻断命中；`2` 参数或目录错误。
- 规则覆盖凭据、私钥、内网地址、个人路径、个人邮箱、内部域名、设备资产与运行数据。
- `[阻断]` 项必须清零；`[复核]` 项需要人工判定。测试夹具、占位提示、i18n key、第三方维护者邮箱等属常见误报，判定理由应记录在发布记录中。
- 公开仓库默认使用通用规则。组织内部名称等无法通用识别的词表只在私有发布流程中传入 `--denylist`，不写入本仓库与 CI 配置。

## 约束

- 脚本使用 Node.js 内置模块，不依赖第三方包，无需安装依赖即可运行。
- 默认只读检查；涉及删除、格式化、联网、数据库或 Git 的动作必须显式传参并取得授权。
- 结果区分通过、失败、跳过与未运行；被环境阻断时不得把未执行报告为通过。
- `verify.mjs` 建立后在此补充真实用法、参数、退出码和覆盖范围，并同步[根约定](../AGENTS.md)的验证要求；在此之前不提供不可执行的入口。
- 目录规划见[目录规划](../docs/项目目录规划.md)。
